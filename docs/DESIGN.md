# Epoch 产品设计

状态：Draft v0.4
日期：2026-07-26

> v0.4 变更摘要：ETF 穿透改为根据当前持仓自动发现与按需刷新，调仓新增基金无需人工维护产品权重；外部来源失败时显示最后可信或待穿透状态。v0.3 已完成策略与券商接入边界对齐。

## 1. 产品定义

Epoch 是为个人 IBKR 卫星仓构建的投资控制台。它将账户数据、投资研究和投资策略连接成可追溯的决策闭环，帮助所有者完成持仓管理、风险管理、事件响应和复盘。

Epoch 负责事实数据、客观计算、策略校验和长期记录；外部 Agent 根据 Epoch 提供的数据与策略完成投资研究和语义判断；所有者作出最终决定并在券商端手工执行。Epoch 不直接创建或提交真实订单。

## 2. 产品目标

### 2.1 投资记录

- 同步 IBKR 账户、持仓、交易、股息、费用、现金流和公司行动；
- 重建历史持仓、组合净值与绩效；
- 记录系统信号、Agent 建议、最终决定和实际执行结果；
- 支持日常、周度、月度、季度和平仓后复盘。

### 2.2 持仓分析

- 展示净值、收益率、回撤、波动率、Sharpe Ratio、Sortino Ratio 及与 `.NDX` 的对比；
- 完成收益归因与持仓穿透；
- 展示发行人、ETF 底层持仓、行业、主题、币种和因子暴露；
- 帮助所有者理解组合收益和风险由何而来。

### 2.3 风险管理

- 计算前瞻波动率、组合波动率 σₚ、stress σₚ 与实际权重对目标权重的偏离；
- 计算 RC、风险/资金比、乖离度、CVaR、压力情景和回撤（均为监控呈现）；
- 跟踪波动率漂移 σᵢ/σᵢ⁰，在 1.5× / 2.0× 分级提示复核；
- 展示相关性、期权市场、杠杆与拥挤度等判断素材；
- 按《投资策略》执行提示、复核待办和唯一硬卡口校验；
- 为调仓意向提供可重现的通过、否决或修正结果。

> 目标权重由所有者按权重档位人工给出，Epoch **不求解权重**。数学模型只用于风险度量与监控呈现。

### 2.4 信息与事件跟踪

- 跟踪财报、公司指引、宏观数据、行业发布与政策事件；
- 将事件组织为近区和远区事件视界；
- 识别即将进入近区但缺少预案的事件；
- 保存单标的分支、主线分支、特事特看记录和后续复盘。

### 2.5 Agent 辅助投研

- 向 Codex、Claude 等外部 Agent 提供受限、结构化、可审计的 Skills & APIs；
- 让 Agent 使用与 Epoch 相同的策略版本、组合数据和风险计算；
- 接收、审核、保存和复用 Agent 生成的结构化研究、预案、调仓意向和复盘；
- 第一版使用一个能力完整的通用投资 Agent，不提前拆分多个专用 Agent。

### 2.6 目标用户

唯一用户是系统所有者。系统可以管理多个 IBKR 子账户或虚拟组合，但不建设组织、租户、客户和审批流。

### 2.7 非目标

- 自动交易或无人确认的订单执行；
- 高频、Tick 级或日内交易系统；
- 盘中行情轮询、盘中持仓探测与任何需要常驻券商会话的接入（TWS API / Client Portal Gateway）；
- 在 Epoch 内建设重型通用研究工作台；
- 第一版拆分多个公司研究、事件分析、持仓复核或组合复盘 Agent；
- 面向公众的证券推荐；
- 多租户、社交、跟单或客户账户管理；
- 使用单一 AI 分数替代投资判断或组合风险分析；
- 自建覆盖所有资产的通用金融终端。

## 3. 产品原则

### 3.1 单用户优先 & 本地优先

- 只解决所有者真实存在的问题，不为潜在商业化预埋复杂功能。
- 完整持仓、成本、交易记录和投资日志默认保存在本地。外部 Agent 只获得完成任务所需的最小上下文。

### 3.2 事实、判断与决定分离

- 外部数据和客观计算是事实层；
- Agent 研究、语义解读和调仓意向是判断层；
- 所有者的确认、修改或拒绝是决定层；
- 三者分开保存，不以 Agent 输出覆盖事实或最终决定。

### 3.3 计算、判断与收口分离

- Epoch 计算量化信号并呈现当前状态，不用代码替代产业和语义判断；
- 外部 Agent 结合策略、证据与语境生成明确的判断和调仓意向；
- Epoch 对调仓意向重新执行硬卡口校验，校验结果具有机械否决权；
- Agent 的理由和置信度不能突破 σₚ ≤ 45%。

> 硬卡口只有一条。其余所有指标均为呈现，是否行动由所有者判断并留痕——**卡口是底线，不是目标**。

### 3.4 人在回路中 & 交易权限隔离

Epoch 对券商交易权限保持只读。系统可以写入研究、预案、建议、决定和复盘，但不能创建或提交真实订单。

## 4. 角色与权责

### 4.1 Epoch

- 同步、对账并保存可重算的事实数据；
- 生成组合绩效、持仓穿透和风险计算；
- 管理事件视界、预案状态和策略版本；
- 对调仓意向执行确定性合规校验；
- 保存 Agent 任务、人工决定和后续复盘。

### 4.2 外部 Agent

- 研究主线、候选标的与现有持仓；
- 完成六因子结构化评估及事实、假设、推论的置信度分析；
- 识别催化剂、证伪条件和候选替代标的；
- 编写事件预案并在事件发生后生成判断；
- 判断波动是特质性还是系统性；
- 生成调仓意向和周期复盘。

### 4.3 所有者

- 审核 Agent 使用的证据、因子评估与判断；
- 确认、修改或拒绝 Agent 生成的调仓意向；
- 对特事特看、策略参数和最终投资决定负责；
- 在券商端手工执行交易；
- 记录实际执行与系统意向的差异。

## 5. 信息架构

### 5.1 Operations

> 回答“今天有什么必须处理”。

- 当日数据同步和计算状态；
- 数据过期、计算失败和 σₚ 卡口越限；
- 波动率漂移分级提示与待书面记录的复核项；
- 监控盘异常高亮与权重偏离；
- 待执行的回补批次与临近的强制时限；
- 近区事件、缺失预案和即将过期的催化剂；
- 待发起的 Agent 任务；
- 待审核的研究、预案、调仓意向与复盘。

### 5.2 Portfolio

> 回答“组合发生了什么，现在持有什么”。

- 账户、持仓和账本；
- 净值、收益率、回撤和基准对比；
- 收益归因；
- 发行人、ETF、行业、地域、币种和主题穿透；
- ETF 调仓后自动发现并按需刷新成分；来源不可用时展示快照日期、过期或待穿透状态；
- 历史持仓和组合快照。

### 5.3 Allocation & Risk

> 回答“应该持有多少，当前是否越过风险红线”。

- 前瞻波动率及其输入数据、估计器口径（SHAR-IV-J / 降级 / 日频近似）、模型版本和可用性；
- 权重档位、三行理由与目标权重；
- 实际权重、目标权重和执行偏离；
- 组合波动率 σₚ 与卡口余量、stress σₚ（ρ = 0.90）；
- 波动率漂移 σᵢ/σᵢ⁰ 与 σₚ/σₚ⁰，含分级提示与复核结论；
- RC、风险/资金比 RCᵢ/wᵢ、乖离度 D_w / D_r、相关性聚类、CVaR、压力测试和回撤；
- 持仓穿透与风险来源解释；
- GEX、指数隐波、隐含相关性、put skew、杠杆和拥挤度等判断素材；
- 硬卡口的校验结果、余量和否决原因；
- 风控减仓后的回补批次状态与强制时限倒计时。

成本价与浮盈状态仅用于账本、税务批次和行为复盘，不进入本域的权重计算或风险判定。

### 5.4 Journal

> 回答“当时为什么这样做，后来结果如何”。

- 当时的组合快照、数据输入和风险计算；
- Agent 生成的主线研究、六因子结构化评估和候选标的比较；
- 事实、假设、推论、引用来源和置信度；
- 催化剂、证伪条件、事件预案和特事特看记录；
- Agent 判断和调仓意向；
- 硬约束校验、最终决定、理由和实际执行；
- 验证指标、复核日期、后续评价和参数校准。

### 5.5 Skills & APIs

> 让一个外部投资 Agent 可以完成不同类型的研究与判断任务。

第一版的通用 Agent 支持以下任务类型：

1. `research_candidate`：研究和比较候选标的；
2. `review_position`：复核现有持仓；
3. `review_portfolio`：复核整个组合；
4. `prepare_event`：为近区事件编写预案；
5. `assess_event`：事件发生后匹配预案并提出动作；
6. `propose_rebalance`：生成调仓意向；
7. `run_review`：生成日常、周度、月度或季度复盘。

Agent 可以写入研究结果、预案、建议和复盘；不能修改账本、客观风险计算、投资策略、策略参数或最终决定，也不能创建真实订单。

## 6. 核心工作流

### 6.1 每日运行

1. 导入上一交易日的 IBKR Flex 账本；
2. 对账交易、股息、费用、现金和公司行动；
3. 更新持仓、组合表现、基准对比和穿透分析；
4. 更新日频市场数据与客观风险信号；
5. 计算波动率、σₚ、stress σₚ、RC、CVaR 和压力情景；
6. 检查 σₚ 卡口、波动率漂移分级与回补批次触发条件；
7. 滚动事件视界，识别缺少预案的近区事件；
8. 生成当日待办和建议发起的 Agent 任务，不直接修改仓位。

> 每日运行只做日终批量计算，不进行盘中轮询或高频探测。

### 6.2 候选标的研究与入场

1. 所有者或 Agent 将标的加入候选范围；
2. Agent 调用 Epoch 数据与《投资策略》完成六因子结构化评估；
3. Agent 记录主线、叙事阶段、催化剂、有效期和证伪条件；
4. Agent 将事实、假设和推论分开，附上来源与置信度；
5. 所有者审核并确认或修改因子评估与权重档位；
6. Epoch 仅记录已确认的权重档位与三行理由，不自行合成目标权重；
7. 调仓意向通过 σₚ 卡口与候选池来源校验后，交由所有者决定是否执行。

### 6.3 事件预案与响应

1. 事件进入近区后，Epoch 检查是否存在预案；
2. 缺少预案时，系统生成红旗并建议发起 `prepare_event`；
3. Agent 编写单标的分支和必要的主线分支；
4. 所有者审核后将预案标记为已确认；
5. 事件发生后，Agent 优先匹配已确认预案并生成调仓意向；
6. 预案外重大事件必须按《投资策略》进入特事特看通道；
7. Epoch 对调仓意向执行硬约束校验，所有者完成最终决定。

### 6.4 波动率变化响应

1. Epoch 计算 σₚ、stress σₚ、相关性、skew、杠杆和拥挤度等客观信号；
2. σₚ 越限时触发风控调仓；未越限但监控盘异常时只提示复核，不强制动作；
3. Agent 结合持仓与市场语境，判断波动是特质性、系统性还是信号混合；
4. Agent 生成横向换仓、减总仓或继续观察的调仓意向；
5. Epoch 对意向重算目标组合并执行 σₚ 卡口与候选池来源校验；
6. 所有者确认、修改或拒绝意向；
7. 减仓落地后建立回补计划，按批次条件与强制时限跟踪至完成。

### 6.5 季度重构

- 在关键持仓与候选标的当季财报基本披露完毕后启动；
- 通过 Agent 重新评估主线、产业周期、持仓和候选标的；
- 重新确认六因子结构化评估、权重档位、催化剂和证伪条件；
- 重算 σₚ 与 stress σₚ，重置 σᵢ⁰ / σₚ⁰ 锚点；
- 复盘特事特看是真例外还是预案缺陷；
- 仅在《投资策略》允许的平静期修改参数。

### 6.6 周期复盘

- **日常**：汇总需要关注的新证据、风险变化、预警、触发与当日建议；
- **每周**：总结持仓变化、研究更新、事件和执行差异；
- **每月**：比较组合与基准，完成收益归因和组合健康度分析；
- **每季度**：评估决策质量、命题验证、预案覆盖、模型偏差和策略参数；
- **平仓后**：复盘完整决策过程，不只评价最终盈亏。

## 7. 关键页面

### 7.1 首页 / Operations

首页不追求展示最多信息，只回答：

- 今天的数据和计算是否正常？
- 哪些风险发生了实质变化？
- 哪些事件即将进入近区但仍缺少预案？
- 哪些交易条件已经触发？
- 哪些 Agent 任务需要发起，哪些结果需要审核？
- 哪些事项必须由所有者处理？

### 7.2 Portfolio

- 组合与基准表现；
- 当前持仓与历史持仓；
- 收益归因；
- 持仓穿透和数据健康。

### 7.3 Allocation & Risk

- 实际权重、目标权重及偏离；
- 波动率、σₚ 与卡口余量、stress σₚ、波动率漂移、RC、CVaR、压力测试和回撤；
- 市场结构与机制情报；
- σₚ 卡口检查与调仓意向校验；
- 回补批次进度与强制时限。

### 7.4 Journal

- Agent 研究、因子评估、权重档位理由和置信度分析；
- 事件视界、预案和特事特看记录；
- 建议、硬约束结果、最终决定和实际执行；
- 日常、周度、月度、季度和平仓后复盘。

Agent 研究从 Operations、Portfolio、Allocation & Risk 或 Journal 的相关对象上下文发起，结果统一进入 Journal，第一版不建设独立的重型 Research 页面。

## 8. 产品边界

《投资策略》是选股、仓位与运行规则的唯一来源。本文只定义产品需要支持的能力、信息和交互闭环，不重复定义具体模型、公式、阈值或交易规则。

当《投资策略》更新时，Epoch 应通过版本化策略与结构化规则适配变化，不在页面、Agent Prompt 或临时逻辑中建立第二套规则。
