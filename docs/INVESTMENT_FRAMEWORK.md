# Epoch 投资框架

状态：待所有者定义  
日期：2026-07-20

## 1. 文档定位

这份文档定义 Epoch 应当遵循的投资原则、研究流程、风险政策和仓位规则。

它与产品设计、技术实现相互独立：

- 产品设计决定系统提供什么体验；
- 技术架构决定系统如何可靠实现；
- 投资框架决定系统依据什么原则分析和提出建议。

当前文档只建立框架，不擅自假设所有者采用价值、成长、趋势或其他具体策略。尚未确认的内容必须保持显式空白，不能由模型自行补齐。

## 2. 框架治理

### 2.1 唯一规则来源

投资原则、证据政策、风险限制和仓位方法以 `frameworks/` 中的版本化文件为唯一来源。UI、计算代码和 Agent Prompt 只引用它们。

### 2.2 版本化

每次修改框架必须记录：

- 修改内容；
- 修改原因；
- 生效日期；
- 适用策略；
- 是否影响历史评价；
- 修改者确认。

历史决定继续绑定当时使用的框架版本。

### 2.3 策略与组合分离

系统允许不同策略拥有不同研究模板、持有期限和风险参数，但组合级硬限制对所有策略生效。

## 3. 待定义的投资使命

需要所有者明确：

- 卫星仓存在的目的；
- 相对于核心仓承担什么角色；
- 目标投资期限；
- 可接受的永久损失与阶段性回撤；
- 期望超越的基准；
- 不允许投资的资产或行为；
- 何种情况下现金也是主动仓位。

建议最终形成一段不超过 150 字的 Investment Mandate。

## 4. 策略定义模板

每个策略至少包含：

```yaml
name:
objective:
universe:
edge_hypothesis:
holding_period:
benchmark:
entry_conditions:
add_conditions:
trim_conditions:
exit_conditions:
position_sizing:
risk_limits:
review_frequency:
```

可能存在的策略类型仅作为示例，不代表已经采用：

- 高质量成长；
- 估值修复；
- 特殊事件；
- 周期反转；
- 主题或宏观表达。

## 5. 投资假设

每个持仓必须绑定一个版本化 Thesis，至少回答：

1. 一句话投资假设是什么？
2. 市场可能错误定价了什么？
3. 这项判断依赖哪些事实和推断？
4. 主要催化剂是什么？
5. 最强的反方解释是什么？
6. 哪些可观察事实会削弱或证伪假设？
7. 预期持有期限是什么？
8. 为什么这个证券是表达该观点的合适工具？

未建立有效 Thesis 的持仓应被标记为 `unclassified`，而不是让模型事后补写理由。

## 6. 证据政策

### 6.1 来源层级

建议按以下优先顺序评价证据：

1. 监管文件、公司正式公告和原始数据；
2. 财报电话会、管理层原话和行业官方资料；
3. 具有编辑责任的专业媒体；
4. 研究机构和专家二手分析；
5. 社交媒体、论坛和匿名消息。

低层级来源可以作为线索，但不能单独构成高置信度事实。

### 6.2 事实主张

系统先从材料中提取可核查的 Claim，再判断：

- 来源是否直接支持该主张；
- 是否存在独立佐证；
- 是否与已有证据冲突；
- 信息在何时生效；
- 是否可能已经被市场预期。

### 6.3 事实与观点

每条研究内容必须标记为：

- `fact`：来源直接支持；
- `inference`：基于事实的推断；
- `opinion`：主观判断；
- `unknown`：证据不足。

## 7. 风险体系

风险分为四类：

1. **组合风险**：集中度、相关性、波动、回撤、流动性和币种；
2. **持仓风险**：仓位大小、流动性、财务质量和事件敏感度；
3. **假设风险**：核心论点被支持、削弱或证伪；
4. **事件风险**：新闻、公告、财报、监管和公司行动。

系统展示原始指标、规则状态和建议动作，不使用一个总分掩盖细节。

## 8. 事件评价

每个事件分别保存以下输入，范围标准化为 0–1，影响方向除外：

- `source_quality`：来源质量；
- `entity_relevance`：与持仓或假设的相关性；
- `claim_confidence`：事实主张可信度；
- `novelty`：相对于已有信息的新颖度；
- `impact_magnitude`：潜在影响强度；
- `impact_direction`：`-1 / 0 / +1`；
- `time_decay`：随时间衰减的有效性；
- `thesis_sensitivity`：投资假设对该事件的敏感度。

候选事件强度：

```text
event_strength =
  source_quality
  × entity_relevance
  × claim_confidence
  × novelty
  × impact_magnitude
  × time_decay
```

该数值只描述事件强度，不直接等于调仓比例。

## 9. 仓位框架

具体仓位公式尚待所有者确认。系统至少需要区分：

- 初始仓位；
- 正常目标区间；
- 最大仓位；
- 组合级风险预算；
- 单一发行人和共同主题上限；
- 流动性约束；
- 允许加仓、冻结加仓和退出复核的条件。

任何仓位建议都必须同时考虑：

- 当前权重与目标区间；
- 投资假设置信度及其变化；
- 与其他持仓的共同暴露；
- 流动性和交易成本；
- 估值情景和潜在永久损失；
- 组合级硬限制。

模型不能仅根据新闻情绪直接计算目标权重。

## 10. 有限建议动作

Epoch 只允许输出有限、可审计的动作：

- `no_action`：信息不足、无实质影响或已被已有判断覆盖；
- `watch`：指定需要继续观察的验证条件；
- `review`：触发人工复核；
- `freeze`：暂停加仓；
- `reduce_range`：建议降低目标权重区间；
- `increase_range`：建议提高目标权重区间；
- `exit_review`：投资假设可能失效，进入退出复核。

每个动作必须附带：

- 触发规则；
- 支持证据；
- 最强反方解释；
- 建议失效条件；
- 复核期限。

## 11. 建仓、加仓与退出清单

### 11.1 建仓前

- 投资假设已建立；
- 证据与反方证据已记录；
- 失效条件可观察；
- 策略与持有期限明确；
- 初始、正常和最大仓位已定义；
- 与现有组合的共同暴露已检查；
- 下一次强制复核日期已设置。

### 11.2 加仓前

- 加仓原因来自假设增强、赔率改善或组合再平衡；
- 不是仅因为价格下跌；
- 未触发冻结加仓条件；
- 加仓后仍符合组合级限制；
- 新证据与原 Thesis 版本关系明确。

### 11.3 退出复核

- 核心假设被证伪；
- 风险收益比不再满足策略要求；
- 出现更优的资本配置机会；
- 达到策略规定的退出条件；
- 持仓因规模或相关性违反硬限制。

退出规则的具体优先级仍需所有者确认。

## 12. 复盘框架

复盘分别评价：

- **过程质量**：信息是否充分、规则是否遵守；
- **判断质量**：关键假设是否合理；
- **执行质量**：仓位、时机和交易成本；
- **结果**：绝对收益、相对收益和承担的风险；
- **可迁移经验**：应保留、修改或删除哪条规则。

盈利不自动证明决定正确，亏损也不自动证明决定错误。

## 13. Agent 使用政策

Agent 可以：

- 汇总证据；
- 提取事实主张；
- 生成反方论证；
- 检查规则；
- 提出有限建议动作；
- 生成结构化复盘草稿。

Agent 不可以：

- 隐瞒证据缺口；
- 将推断写成事实；
- 自行修改投资框架；
- 自行提高置信度以满足仓位要求；
- 写入真实订单；
- 替所有者作出最终决定。

## 14. 首批待确认问题

在实现策略引擎前，需要所有者回答：

1. 卫星仓的投资使命是什么？
2. 主要投资标的和明确排除项是什么？
3. 典型持有期限是多少？
4. 建仓逻辑主要属于哪些策略？
5. 单一持仓、发行人和主题的最大权重是多少？
6. 可接受的组合回撤和风险预算是多少？
7. 加仓更看重假设增强、估值改善，还是二者必须同时满足？
8. 哪些条件属于必须退出，哪些只触发复核？
9. 默认基准和报告币种是什么？
10. 哪些判断必须由所有者手工输入，不能由模型推断？
