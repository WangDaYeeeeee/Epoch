# Epoch 实施路线

状态：Draft v0.2  
日期：2026-07-20

## 1. 文档职责

本文只负责项目阶段、交付物、依赖关系和验收标准，不承载产品需求、技术设计或投资规则。

- 产品范围与用户体验见 [DESIGN.md](DESIGN.md)；
- 系统结构与工程约束见 [ARCHITECTURE.md](ARCHITECTURE.md)；
- 投资原则与策略规则见 [STRATEGY.md](STRATEGY.md)。

## 2. 实施原则

1. 先得到可信账本，再建设风险智能；
2. 先使用合成和脱敏数据，再接入真实账户；
3. 先只读和影子运行，再单独评估交易能力；
4. 每个阶段都有可独立验证的结果；
5. 不因未来可能商业化而增加当前复杂度。

## 3. 阶段路线

### Phase 0：项目基础与个人配置

目标：建立可重复开发环境，确定首批产品和投资配置。

交付：

- 仓库目录、开发环境和基础 CI；
- Web、API 和 PostgreSQL 骨架；
- 数据库迁移机制；
- 时间、货币和标识符约定；
- 合成 Demo 数据集；
- 投资框架文件结构；
- 个人配置的初始版本。

需要所有者确定：

- 卫星仓账户边界；
- 默认基准；
- 基础币种和报告币种；
- 投资使命与首个策略；
- 首批风险硬限制。

完成标准：

- 任意开发环境可一条命令启动；
- 固定输入可以重现相同计算结果；
- 仓库不包含真实凭证或真实账户数据。

### Phase 1：可信账本与组合表现

目标：准确回答“组合发生了什么”。

交付：

- IBKR Flex 原始报表导入；
- 幂等同步和不可变原始数据留存；
- 交易、现金、费用、股息和公司行动归一化；
- 每日 NAV、TWR、MWR 和回撤；
- 基准比较；
- 数据健康与对账视图。

完成标准：

- 选定历史区间与 IBKR statement 对账；
- 差异可以定位和解释；
- 重复导入不会生成重复记录；
- 关闭所有模型后仍能完整运行。

### Phase 2：盘中状态与持仓穿透

目标：准确回答“组合现在暴露于什么”。

交付：

- IBKR Web API 只读连接；
- 盘中持仓、账户摘要和行情状态；
- 证券与发行人映射；
- 行业、地域、币种和自定义主题标签；
- 集中度、重叠和风险预算视图；
- 数据过期和连接状态提示。

完成标准：

- 可以从组合异常下钻到持仓与暴露来源；
- 可以识别不同证券背后的共同发行人或主题；
- IBKR 断线不会污染最后可信状态。

### Phase 3：投资假设与决策日志

目标：准确回答“为什么持有，为什么行动”。

交付：

- Thesis、Evidence、Claim 和 Decision 模型；
- 版本化投资假设；
- 建仓、加仓和退出复核清单；
- 决策时组合快照；
- 周度、月度和持仓结束复盘。

完成标准：

- 一次建仓、复核、调仓和平仓可以完整还原；
- 历史决定绑定当时的策略版本；
- 无 Thesis 持仓能被明确识别。

### Phase 4：事件风险引擎

目标：把新增证据转化为可解释的待处理风险。

交付：

- 公告和新闻接入；
- 去重、时间校验和实体关联；
- 事实主张提取与来源评价；
- RiskEvent 和 RiskAssessment；
- 硬限制、规则状态和有限建议动作；
- Risk Inbox；
- 影子运行、误报和漏报反馈。

完成标准：

- 每个提示可展开到原始来源、事实主张和触发规则；
- 系统建议与最终决定分开保存；
- 模型失效时，规则风险仍然正常运行；
- 经过预定影子运行周期后再讨论更高权限。

### Phase 5：Epoch Skills

目标：让 Epoch、Codex 和 Claude 共享同一投资框架。

交付：

- 公司研究 Skill；
- 事件影响 Skill；
- 持仓复核 Skill；
- 组合复盘 Skill；
- 统一 JSON Schema 和本地工具接口；
- AgentRun 审计与回归数据集。

完成标准：

- 不同 Agent 输出相同结构；
- 所有结论有框架版本和来源；
- Agent 不能读取未授权字段；
- Agent 不能修改账本、策略规则或真实交易。

### Phase 6：长期运行优化

候选范围：

- 数据源失效监控与冗余；
- 因子、情景和压力测试；
- 研究记忆检索；
- 决策质量统计；
- 多设备只读访问；
- 订单草稿能力的独立安全评审。

Phase 6 不属于 MVP 承诺。

## 4. MVP 定义

MVP 包含 Phase 0 至 Phase 5，但每个阶段都应产生可使用的增量，不等待所有模块完成后一次性交付。

MVP 端到端验收：

1. 导入至少一年的 IBKR 历史数据；
2. 与指定基准比较收益和回撤；
3. 从回撤下钻到证券和暴露贡献；
4. 识别共同主题或发行人风险；
5. 新证据关联到持仓和投资假设；
6. 生成可解释的复核或冻结加仓建议；
7. 所有者接受、修改或拒绝建议；
8. 月度复盘还原当时的证据、建议和决定；
9. Codex 或 Claude 生成符合框架的结构化持仓复核；
10. 外部模型不可用时，账本和确定性风险功能不受影响。

## 5. 里程碑依赖

```text
Phase 0
   ↓
Phase 1 可信账本
   ↓
Phase 2 持仓穿透
   ↓
Phase 3 投资假设与日志
   ↓
Phase 4 事件风险
   ↓
Phase 5 Skills
```

Phase 3 的投资规则定义可以与 Phase 1、Phase 2 并行讨论，但事件风险和 Skills 不应早于领域数据与策略边界。

## 6. 首个开发切片

建议第一个切片只完成：

1. 使用合成数据导入一组交易和现金流；
2. 生成每日持仓和 NAV；
3. 计算一个基准的累计收益；
4. 显示组合与基准曲线；
5. 展示账本守恒和数据健康状态。

这个切片验证最重要的领域模型和计算口径，不依赖真实 IBKR 凭证、新闻或模型。
