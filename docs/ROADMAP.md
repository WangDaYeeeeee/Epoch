# Epoch 实施路线

状态：Draft v0.5
日期：2026-07-25

> v0.5 变更摘要：对齐《投资策略》大改——硬约束收敛为唯一卡口 σₚ ≤ 45%，移除 ERC 求解与 θ 权重合成，HAR-IV-J 改为 SHAR-IV-J（符号跳跃 ΔJ），新增波动率漂移锚点、权重档位与回补状态机；确定不接入 TWS/Client Portal Gateway，不做盘中高频探测。

## 1. 文档职责

本文只负责项目阶段、交付物、依赖关系和验收标准，不承载产品需求、技术设计或投资规则。

- 产品范围与用户体验见 [DESIGN.md](DESIGN.md)；
- 系统结构与工程约束见 [ARCHITECTURE.md](ARCHITECTURE.md)；
- 投资原则与策略规则见 [STRATEGY.md](STRATEGY.md)。

## 2. 实施原则

1. 先得到可信账本，再建设组合与风险智能；
2. 先建立确定性计算和收口，再接入 Agent 判断；
3. 先使用合成、脱敏和历史数据，再接入真实账户；
4. 每个阶段都产生可独立验证的增量，不等待所有模块完成后一次交付；
5. Agent 只产生研究、判断和意向，不替代计算引擎、Policy Gate 或最终决定；
6. 全程保持券商交易权限只读，真实交易在系统外手工执行；
7. 不因未来可能商业化或拆分多 Agent 而增加当前复杂度。
8. 保持单一 Git 仓库和一条本地启动链路；TypeScript 控制面与 Python 计算面以版本化契约隔离。

- 数据库迁移与轻量任务调度机制；

- 合成 Demo 数据集；

- 卫星仓账户边界；

### Phase 3：确定性风险引擎与 Policy Gate

目标：准确回答“应该承担多少风险，一个调仓意向是否越过红线”。

本阶段分为递进的两个内部里程碑：

#### Phase 3A：风险核心与可重现管线

交付：

- `CalculationRun` 与输入/输出快照；
- 单仓库内的 Python Analytics Service、内部健康检查与版本化计算 API；
- TypeScript Scheduler 到 Analytics Service 的超时、重试、幂等、契约校验和失败记录；
- 历史波动率、协方差、250 日相关性矩阵与基线 HAR-RV；
- **σₚ 卡口所需的降级估计器：60 日已实现波动率（Garman-Klass）**——卡口必须先于 SHAR-IV-J 可运行；
- 组合波动率 σₚ 与 stress σₚ（令所有非对角 ρ = 0.90）；
- 监控量：RC、风险/资金比 RCᵢ/wᵢ、乖离度 D_w / D_r、相关性聚类；
- 波动率漂移锚点：调仓时归档 σᵢ⁰ / σₚ⁰，持续计算 σᵢ/σᵢ⁰ 与 1.5× / 2.0× 分级提示；
- 历史 CVaR 与历史崩盘周压力情景（呈现用，不参与收口）；
- 对调仓意向进行组合重算的 Policy Gate：校验 σₚ ≤ 45% 与替代标的候选池来源合规；
- 数据缺失、计算失败与降级状态。

> **与策略 v0.5 的对齐**：硬约束已收敛为唯一卡口 σₚ ≤ 45%。ERC 权重求解、θ 观点权重合成、单标的 RC 硬上限、财报前权重上限、压力测试单周底线与回撤预算触发线**均已从策略中移除**，不再作为交付项；RC、CVaR、压力情景降级为监控呈现。权重由人工按档位给出，Analytics 不求解权重。

#### Phase 3B：SHAR-IV-J 核心预测

交付：

- 日频 OHLC 的已实现波动率口径（Garman-Klass / Parkinson）；
- **符号半方差 RS± 与符号跳跃 ΔJ = RS⁺ − RS⁻ 的口径实现**，默认使用日频近似（窗口内按收益符号的平方和），日内收益为可选升级；
- 每次计算显式标记当期使用的是日内口径还是日频近似，并写入记录表；
- SHAR-IV-J 训练、预测、回测和模型版本；
- IV 外生项 `β_iv·IVₜ`：**数据源待补**，缺失时按降级口径运行；
- IV 缺失、期权不活跃、新上市标的与不适用品种的降级/拒绝策略；
- 预测波动率与实际已实现波动率的误差记录。
- Python 纯计算包、HTTP 服务外壳与黄金样本重放 CLI 共享同一模型实现。

完成标准：

- 固定数据快照、模型、策略和参数版本可重现相同结果；
- σₚ、stress σₚ、RC、CVaR 和压力情景均有黄金样本；
- Policy Gate 可对任意目标持仓输出逐条、可解释的校验结果；
- 数据或模型不可用时显示降级状态，不伪装成正常预测；
- 关闭外部 Agent 后，整个计算与校验管线仍正常运行。

> **跳跃项实现变更**：不再使用双幂变差 BPV 拆连续/跳跃成分。策略明确否决 `RS⁺ / RS⁻ / J` 三项并列（半方差按符号切 RV、跳跃项按连续/跳跃切 RV，是同一量的两种切法，严重共线），改用符号跳跃 ΔJ 单独承载符号信息。
>
> **IV 数据源现状**：不接入 TWS/Gateway 后，IBKR 期权链不再是可用来源。`β_iv` 项与 put skew 目前无数据源，Phase 3B 可在无 IV 的设定下交付。策略已就此写明降级路径——**"估计器可升级，卡口值不变"**——因此 IV 缺失不阻塞 σₚ 卡口运行，也不阻塞 MVP。隐含相关性改用 CBOE 公开隐含相关指数，不依赖自建反算。
- 单条 Docker Compose 命令可启动 PostgreSQL、Web/API、Scheduler 和 Analytics 四个常驻服务，Analytics 不对主机公开端口。

### Phase 4：Operations、事件视界与 Journal

目标：准确回答“今天有什么必须处理，当时为什么这样做”。

交付：

- Operations 首页与每日运行状态；
- 数据过期、计算失败、风险预警、交易触发和硬约束待办；
- 事件、近区/远区事件视界与每日滚动；
- 缺少预案、催化剂过期和季度重构待办；
- Theme、Candidate、FactorAssessment、Evidence 和 Claim；
- **WeightTier（权重档位）与三行理由记录**：盈利预期（含可证伪的锚）、主要风险（须与证伪条件一致）、为什么是这一层；
- **VolatilityAnchor**：调仓时归档的 σᵢ⁰ / σₚ⁰，供漂移提示与复盘对照；
- **RefillPlan / RefillBatch（风控减仓后的回补状态机）**：三批各 1/3、逐批触发条件、卡口连续通过 10 个交易日的强制时限、未执行须书面留痕；
- Catalyst、InvalidationCondition 与 ExitRestriction（**90 天禁回购仅约束主动清仓，风控减仓不适用**）；
- Playbook、PlaybookBranch 与 ExceptionRecord；
- RebalanceIntent、PolicyEvaluation、Decision 和 ExecutionRecord；
- 调仓动作类型含**降级至 QQQ**（卫星仓内保持市场暴露，不转现金）；
- 日常、周度、月度、季度和平仓后复盘。

本阶段允许所有者手工写入研究结果和预案，不依赖 Agent 即可验证完整领域闭环。

完成标准：

- 一次入场、复核、调仓和平仓可以完整还原；
- 历史判断与决定绑定当时的策略、参数、数据和计算版本；
- 事件进入近区但缺少预案时产生明确红旗；
- 预案外动作只能通过特事特看对象留痕；
- 系统建议、机械校验、最终决定和实际执行分开保存；
- 调仓记录表字段与《投资策略》5.1 完全一致；
- 风控减仓后的回补批次状态、强制时限与未执行理由可完整追溯。

### Phase 5：通用 Epoch Investment Agent

目标：让 Codex 或 Claude 通过一个通用 Agent 使用 Epoch 的数据、计算和投资策略完成研究与判断。

交付：

- `epoch-investment-agent` Skill；
- 统一 Agent Gateway、JSON Schema 和本地 CLI/API；
- `research_candidate`、`review_position`、`review_portfolio`；
- `prepare_event`、`assess_event`、`propose_rebalance`、`run_review`；
- 受限查询、有限写入与 Policy Gate 调用权限；
- AgentRun 审计、策略版本、来源引用与人工反馈；
- 固定证据集与回归评估集。

完成标准：

- 一个 Agent 可根据 `task_type` 完成全部七类任务；
- 研究结果区分事实、假设和推论，并提供来源与置信度；
- 六因子评估与权重档位建议包含支持、反证和"为什么是这一层"的理由；
- Agent 调用 Epoch 生成客观计算和 PolicyEvaluation，不自行写入结果；
- Agent 不能读取未授权字段，不能修改账本、策略、参数、计算、最终决定或真实交易；
- 外部 Agent 不可用时，账本、绩效、风险计算、Policy Gate、Operations 和 Journal 仍正常运行。

### Phase 6：长期运行与模型增强

候选范围：

- 经回测验证的预测增强；
- **日内收益数据源**：将符号半方差 RS± / 符号跳跃 ΔJ 从日频近似升级为严格口径；
- **期权链数据源**：恢复 `β_iv` 外生项与 put skew，需评估不引入常驻会话的获取方式；
- GEX、隐含相关性、融资余额、期权杠杆和拥挤度数据源增强；
- SKHY 的 IV 可得性验证（美股 OTC ADR 无期权链，KRX 单股期权接入待确认）；
- 数据源失效监控与冗余；
- 研究记忆检索与长周期命题追踪；
- 预测误差、置信度、预案覆盖与决策质量统计；
- 将稳定、重复的 Agent 判断下沉为确定性信号或规则；
- 多设备只读访问；
- 订单草稿能力的独立安全评审。

Phase 6 不属于 MVP 承诺。

## 4. MVP 定义

MVP 包含 Phase 0 至 Phase 5。各阶段必须产生可使用增量，但 MVP 结束时必须形成从可信账本到 Agent 判断与人工决定的完整闭环。

MVP 端到端验收：

1. 导入至少一年的 IBKR 历史数据并通过账本对账；
2. 与 `.NDX` 比较收益、回撤和风险；
3. 从绩效异常下钻到证券、发行人、主题和其他暴露来源；
4. 使用版本化的 SHAR-IV-J 或明确标记的降级模型（60 日 Garman-Klass）生成波动率预测；
5. 计算 σₚ、stress σₚ、RC、CVaR、压力情景与波动率漂移倍数；
6. 对一个调仓意向输出可重现、逐条的 PolicyEvaluation；
7. 事件视界发现近区事件缺少预案并生成待办；
8. 通用 Agent 完成一次候选研究、六因子评估、权重档位建议与预案编写；
9. Agent 生成调仓意向，Epoch 独立执行 Policy Gate，所有者确认、修改或拒绝；
10. Journal 还原当时的数据、计算、证据、Agent 判断、校验、决定和实际执行；
11. 外部 Agent 不可用时，账本、风险管线、Operations 与 Journal 不受影响；
12. 系统不具备真实下单能力。

## 5. 里程碑依赖

```text
Phase 0  项目基础 / 策略版本
   ↓
Phase 1  可信账本 / 组合表现
   ↓
Phase 2  持仓穿透 / 市场数据
   ↓
Phase 3  风险计算 / Policy Gate
   ↓
Phase 4  Operations / 事件视界 / Journal
   ↓
Phase 5  通用 Agent
```

可并行的工作：

- SHAR-IV-J 方法细化与 Python 依赖验证可提前开始，但只在 Phase 3 进入生产计算；
- 策略 Schema、Agent 输出 Schema 和回归评估集可与 Phase 2–4 并行设计；
- 事件日历数据源可与 Phase 3 并行接入；
- Agent 不应早于核心领域对象、确定性计算和 Policy Gate。

## 6. 首个开发切片

第一个切片只完成：

1. 使用合成数据导入一组交易和现金流；
2. 生成每日持仓和 NAV；
3. 计算 `.NDX` 基准的累计收益；
4. 显示组合与基准曲线；
5. 展示账本守恒和数据健康状态。

该切片验证最基础的领域模型和计算口径，不依赖真实 IBKR 凭证、期权数据、事件数据或外部 Agent。
