# Phase 2 实施记录

状态：In Progress
开始日期：2026-07-23

## 目标

Phase 2“持仓穿透与市场数据基础”用于回答“组合现在持有什么，又暴露于什么”，并为 Phase 3 的确定性风险计算建立版本化、具备时效与质量说明的输入。

## 当前切片：确定性持仓穿透

首个切片已建立独立的 `exposure` 领域计算：

- 以当前持仓 USD 总市值绝对值计算总敞口，显式标记方法为 `gross-market-value`；
- 将券商特定的美股交易所代码归并到统一市场标识；
- 使用版本化证券分类表建立直接证券到发行人的映射；
- 支持接收 ETF 底层发行人权重，并对未覆盖权重保留“待穿透”桶；
- 聚合发行人、持仓币种和资产类别敞口；
- 在组合 API 和 Portfolio 页面展示发行人覆盖率、各维度权重及缺失的穿透输入；
- 当前 SOXX 尚未接入带日期的官方底层持仓，因此不会把基金管理人误记为经济发行人敞口。

当前真实基线的发行人穿透覆盖率为约 `74.17%`；未覆盖部分为 `US:SOXX`。币种和资产类别由券商持仓事实直接聚合，不依赖发行人分类。

## 第二切片：市场数据时效

市场数据健康检查现已区分“历史覆盖完整”和“当前仍然新鲜”：

- 对全部必需证券和汇率序列分别查找最后有效日期，并使用最早的共同日期作为最后可信市场快照；
- 依据 `.NDX` 交易日历计算应有截止日和交易日滞后，允许最多一个交易日的发布延迟；
- 状态明确分为 `fresh`、`stale` 和 `missing`，过期数据不会继续显示为正常；
- 保存最后成功观测时间；新版行情抓取清单写入权威 `observed_at`；
- 旧清单没有 `observed_at` 时使用文件修改时间作为降级证据，并明确标记为 `filesystem_fallback`；
- 组合 API 和页面展示最后有效日期、交易日滞后与“需关注”状态；
- 时效告警不改变 Phase 1 历史账本的对账结论，账本可信度和行情新鲜度保持为两个独立维度。

在 2026-07-23 的验收检查中，现有必需行情的共同最新有效日为 `2026-07-16`，状态为 `stale`。这反映当前数据确实需要刷新，不是测试伪造的告警。

## 第三切片：OHLCV 与 Analytics 市场输入契约

日频行情已从仅收盘价扩展为兼容的 OHLCV 数据层：

- 新增 `market-bars.csv`，字段包含有效日、证券标识、OHLC、成交量、币种、来源、来源代码和 `observed_at`；
- 原有 `market-prices.csv` 继续生成并供 Phase 1 账本估值使用，不改变历史重放口径；
- OHLCV 校验检查日期、正数价格、最高/最低价不变量、非负成交量、观测时间、重复键和当前持仓覆盖；
- 现有本地原始响应已离线生成 11,148 条历史 bar；当前 5 个市场证券覆盖 5/5，共 1,857 条有效 bar，0 条无效、0 条重复；
- FX 继续使用日收盘价完成 USD 对齐；因上游部分 FX 日内 high/low 字段不满足价格不变量，不将其冒充通过校验的证券 OHLCV；
- 联网抓取脚本后续会同时生成收盘价、OHLCV、拆股和带权威时间戳的原始清单；
- 新增 `market:normalize`，可在不联网、不泄露标的列表的情况下从既有私有原始响应重新生成标准化行情。

已新增 `portfolio-market-input/1.0` JSON Schema，冻结以下 Phase 3 输入约定：

- USD 基础币种与 `.NDX` 交易日历；
- decimal 单位的拆股调整后、收盘到收盘 USD 价格收益；
- 同有效日收盘汇率；
- 股息不包含在该价格收益序列中；
- 数量和市值使用十进制字符串；
- 缺失值策略、共同日期区间、质量状态和来源观测时间均为必填。

该 Schema 已由 Python `jsonschema` 回归样本验证。模型专属输出字段仍将在 Phase 3 风险模型实现前追加，不复用含糊的无单位数值。

## 第四切片：IBKR 只读连接状态

已建立不扩大交易权限的 IBKR Web API 连接状态模型：

- 未配置 `IBKR_WEB_API_URL` 时返回 `not_configured`，不会发起网络请求，历史 Flex 账本继续可用；
- 配置后仅调用 `GET /iserver/auth/status` 检查网关和会话，不调用订单创建、修改或提交端点；
- 状态区分 `connected`、`authentication_required`、`unavailable` 和 `not_configured`；
- 保存检查时间、受限端点、会话连接/认证/竞争状态及可见原因；
- `capability` 固定为 `read_only`，不会根据券商会话能力提升 Epoch 权限；
- `/api/health` 和 Portfolio 数据健康区域均展示该状态；
- 网络超时为 3 秒，连接失败显式降级，不污染最后可信历史快照。

本切片只完成连接状态与安全边界。

## 边界变更：终止券商实时接入（2026-07-25）

原计划的"IBKR Web API 只读连接"与"按需盘中持仓、账户摘要和行情状态"两项交付**已从 Phase 2 移除**，不再是完成前提。

原因：Client Portal Gateway 与 TWS API 均需常驻会话和每日交互式二次认证，与 Epoch"不做盘中高频信息探测"的产品边界及无人值守部署冲突。账本改由 IBKR Flex Web Service 单独承担——无状态 HTTPS、日频拉取、token 支持 IP 白名单与最长一年有效期，适合固定 IP 的长期自动运行。

影响与处置：

- 第四切片已实现的 `ibkr-web` 连接状态检查**保留为可选能力，默认不启用**。未配置 `IBKR_WEB_API_URL` 时返回 `not_configured` 且不发起网络请求，已经是正确的默认行为，无需改动代码；
- 组合风险计算只依赖日频 OHLC 与汇率，不依赖券商实时行情；
- 期权链随之失去数据源。`β_iv` 外生项与 put skew 标记为待补，σₚ 按策略 2.1 内置降级口径（60 日 Garman-Klass）运行——**估计器可升级，卡口值不变**，因此不阻塞卡口运行，也不阻塞 MVP；
- 隐含相关性改用 CBOE 公开隐含相关指数，不再自建反算（反算需成分 IV）。

详见 [ROADMAP.md](../ROADMAP.md) Phase 2 的盘中数据边界声明与 [ARCHITECTURE.md](../ARCHITECTURE.md) 6.1 券商接入边界。

## 数据源调查：SOXX 官方端点（2026-07-25）

iShares 官方 CSV 来源当前不可程序化使用，但这只影响该来源适配器，**不再构成 ETF 穿透整体阻塞**。

已在所有者授权下尝试联网抓取 iShares 官方持仓 CSV，端点取自 SOXX 产品页自身引用的地址：

```
https://www.ishares.com/us/products/239705/ishares-semiconductor-etf/1467271812596.ajax?fileType=csv&fileName=SOXX_holdings&dataType=fund
```

响应为服务端门禁：HTTP 200，响应头声明 `content-type: text/csv` 与 `content-disposition: attachment; filename=SOXX_holdings.csv`，但 body 返回产品页 HTML（`x-page-name: products/overview-v3`）。已排除 URL 拼写、产品路径（`ishares-phlx-semiconductor-etf` 与 `ishares-semiconductor-etf` 均试）、`Accept: text/csv` 与 `Referer` 等常规请求头因素，四次尝试均返回 HTML。

**未采用的绕行手段**：先访问页面获取 session cookie 后重放、解析页面内嵌的持仓 JS、伪造更完整的浏览器指纹。以上均属规避对方访问控制，不在"抓取公开数据"的授权范围内，后续接手者同样不应采用。

已验证 SEC EDGAR（iShares Trust，CIK `1100663`）可正常程序化访问，可作为备选。

该调查促成了方案调整：领域层不得依赖单一基金公司的网页端点，也不得为 SOXX 写一次性逻辑。

## 方案调整：通用 ETF Holdings 管线（2026-07-26）

正式链路调整为：

1. 从最新非零持仓自动识别 ETF，不维护待抓取产品白名单；
2. 定义可替换的 `EtfHoldingsProvider`，输入基金标识与可选日期，输出统一的带 `as_of` 成分快照；
3. 优先接入覆盖当前标的的结构化 ETF Holdings API；发行人官方文件、手工 CSV importer 和 SEC N-PORT 分别作为来源兜底与审计来源；
4. 原始响应按哈希不可变留存，标准化快照按 `(fund, as_of, provider)` 追加保存，历史计算只使用当时可得数据；
5. 在调仓分析前或快照超过时效阈值时刷新。新增 ETF 自动进入获取队列，卖出后停止当前刷新但保留历史；
6. 获取失败时沿用最后可信快照并标记 `stale`；从未取得成分时进入“待穿透”，不伪造覆盖率。

因此所有者后续调仓不需要手工寻找或录入 ETF 权重。手工下载仅在自动 Provider 无覆盖或不可用时作为显式兜底。

## 第五切片：ETF Holdings 通用管线

已实现：

- `EtfHoldingsProvider` 契约、免费本地 CSV Provider 与可选 FMP 适配器，输入统一为基金、`as_of`、成分证券、权重、可选持股数和基金内市值；
- 本地 Provider 可直接解析 iShares 下载文件，也支持跨发行人复用的统一 CSV；原始文件留在 Git 忽略的私有目录，内容哈希进入幂等键；
- SEC N-PORT 免费 Provider：通过 EDGAR submissions 发现候选申报，使用注册人 CIK 与基金 Series ID 校验，解析成分 ticker、`pctVal`、份额和 USD 市值；当前登记 SOXX 为 `1100663 / S000004354`；
- Provider chain 支持 `local_csv,sec_nport` 顺序降级，本地文件存在时不会访问 SEC；
- 从最新非零持仓按资产类别自动发现 ETF，并统一券商市场代码；
- point-in-time 快照选择，禁止历史计算使用未来才发布的成分；
- fresh / stale / missing 状态、按时效刷新、失败后保留最后可信快照；
- `fund_holdings_snapshot` / `fund_holding` 追加式数据库模型，来源哈希参与幂等键；
- `pnpm fund-holdings:sync` 可执行入口；只有配置 `FMP_API_KEY` 才会联网；
- 数据库组合读取时自动加载适用快照，并与直接持仓共用发行人聚合逻辑。

## 第七切片：持仓重叠与收益归因

- 发行人重叠按来源证券展开，可同时识别直接持仓与 ETF、多个 ETF 或多种证券背后的共同发行人；
- 重叠结果保留每个来源的 USD 敞口与发行人内部占比，不只给出一个合并百分比；
- 日频收益归因按“期初仓位价格/汇率变化 + 当日成交相对收盘价差及费用 + 股息/利息/费用现金项 + 显式残差”闭合；
- 历史行情为最新份额单位的拆股调整序列，归因会把历史仓位与成交同步换算到相同份额单位；
- 归因只展示 USD 损益贡献，不使用接近零的初始 NAV 生成误导性的累计贡献率；
- 历史期权、子账户和报告时点等无法独立估值部分保留在 residual，并展示可解释比例；
- residual 已按每日估值证据缺口聚合：历史期权、`SUBACCOUNT:7313`、报告时点与无明确缺口的模型残差分别保留；同日多个缺口使用组合原因，不做缺乏证据的金额均摊，且各桶金额与总残差保持恒等。
- 修正卖出成交归因方向，并纳入期初外币现金汇兑损益；缺少历史收盘价时，仅对当日净数量严格为零、现金金额与汇率均完整的日内闭环使用成交现金净额；带价格的非交易持仓调整可作为上市前成本锚点，已覆盖 02259 IPO 获配至首个市场收盘的浮盈。真实基线按 `1 - |残差| / |组合损益|` 计算的闭合比例约为 `91.9%`，无明确估值缺口的模型残差桶已由约 `9,029.20 USD` 降至约 `291.51 USD`。
