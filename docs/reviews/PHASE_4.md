# Phase 4 实施记录

状态：Accepted
开始日期：2026-07-27
验收日期：2026-07-27

## 目标

Phase 4“Operations、事件视界与 Journal”用于回答“今天有什么必须处理，当时为什么这样做”。本阶段保持系统建议、机械校验、所有者决定和实际执行彼此分离。

## 第一切片：确定性 Operations 工作台

已实现纯领域函数生成每日 Operations 快照，并接入 Portfolio 页面：

- 汇总持久化 `operational_alert`，保留来源、严重性、发生次数和最近观测时间；
- 行情 `stale` / `missing` 在没有同源持久化告警时生成待办，避免重复展示；
- 缺少真实组合风险运行或唯一 45% Policy Gate 越界时生成关键事项；
- 发行人或 ETF 穿透不完整时生成覆盖复核事项，并列出缺失证券；
- 已确认执行锚点存在后，1.5× / 2.0× 波动率漂移生成分级书面复核事项；
- 所有事项具有稳定 ID、`critical / action / review` 优先级、`risk / data / coverage` 分类和可核验证据；
- 页面按优先级展示关键、待处理、待复核数量，并明确“不含 Agent 判断、不自动交易”。

本切片不新增第二套告警规则，不持久化派生待办。待办由不可变风险运行、数据健康、持仓覆盖和开放告警确定性重建，因此刷新页面不会制造重复记录。

## 第二切片：事件视界与缺失预案红旗

- 新增 `investment_event` 与一对一 `event_playbook`，区分事件事实与应对预案；
- 事件包含证券、类型、计划日期、来源、观测时间和记录时间；
- 预案明确区分 `draft` 与 `ready`，只有 `ready` 才能解除近区红旗；
- 使用 NDX 交易日历计算事件距离，未来 10 个交易日为近区，周末和休市日不计数；
- 近区缺少就绪预案时确定性生成 Operations 待办；3 个交易日内提升为待处理，其余为待复核；
- `GET/POST/PUT /api/v1/events` 分别读取事件视界、登记事件和保存预案；
- 页面显示事件日期、证券、类型、交易日距离与预案状态；
- 事件 API 不接入新闻发现或 Agent，不允许创建调仓、决定或订单。

数据库迁移、事件/预案持久化、红旗解除状态流已经通过真实 PostgreSQL 集成测试。

## 第三切片：六因子评估与权重档位确认边界

- 新增 `investment_candidate`、追加式 `factor_assessment`、六条 `factor_assessment_item` 与追加式 `weight_tier`；
- 六因子固定为动量、确定性、护城河、盈利质量、盈利上修预期和估值；
- 每个因子分别记录强/中性/弱/信息不足、置信度、主要依据、主要反证、变化方向和最终影响；
- 不计算总分，不设置因子权重，不把定性结论自动映射成仓位；
- 权重档位只接受 `10 / 15 / 20 / 25 / 30 / 35 / 40`；
- 每个档位强制记录盈利预期及可证伪锚、主要风险、对应证伪条件和“为什么是这一层”；
- `confirmed` 权重档位必须引用同一候选标的的 `confirmed` 六因子评估，草稿评估只能产生 proposed 档位；
- 新增 `GET/POST /api/v1/candidates`，支持登记候选、保存六因子评估、保存档位与读取最新确认状态；
- 所有判断对象追加保存，不覆盖历史版本。

该链路已经通过真实 PostgreSQL 集成测试，覆盖“草稿评估不能确认档位”和“确认评估后可确认档位”两条边界。

## 第四切片：Evidence → Claim → FactorAssessment 证据链

- 新增不可变 `research_evidence`，保存来源类型、来源名称、URL、观测时间、生效日期、摘录和 SHA-256 内容哈希；
- 相同来源与内容哈希幂等复用，不因重复导入制造第二份证据；
- `research_claim` 明确区分事实、假设和推论，并保存 `as_of` 与置信度；
- 事实必须引用支持证据；假设和推论必须记录推理依据；
- 同一证据不能同时作为同一命题的支持与反证；
- `claim_evidence` 保留支持/反证角色，`factor_assessment_claim` 将命题连接到同一候选标的的六因子评估；
- 不允许把其他候选标的的命题错误绑定到当前评估；
- 新增 `GET/POST /api/v1/research`，支持保存证据、保存命题、关联评估和读取候选证据链。

证据、命题和关联均为追加式记录，不修改客观行情、账本、风险计算或最终决定。真实 PostgreSQL 集成测试已覆盖支持证据、反证和评估关联的完整状态流。

## 第五切片：Decision → ExecutionRecord → Journal

- 新增追加式 `investment_decision`，引用不可变的 `portfolio-risk-rebalance` CalculationRun；
- 触发类型明确区分风控、临时、特事特看和常规调仓；
- 所有者决定明确区分确认、修改后确认和拒绝，并强制记录理由与后续观察项；
- Policy Gate 未通过的测算只能记录为拒绝，不能被确认或伪装成已批准；
- 新增一对一 `execution_record`，只记录 Epoch 外部完成的实际执行、券商引用和实际权重；
- 被拒绝的决定不能创建执行记录；实际权重不由系统归一化，也不产生订单；
- Journal 查询同时还原当时的目标输入、风险输出、所有者决定和实际执行差异；
- 新增 `GET/POST /api/v1/journal`，并在 Portfolio 页面加入决策日志展示。

真实 PostgreSQL 集成测试覆盖卡口失败拒绝、卡口通过确认、外部执行登记和完整 Journal 读取，证明机械校验、人工决定与实际执行保持分离。

## 第六切片：RefillPlan / RefillBatch 回补状态机

- 只有已经外部执行的风控减仓决定才能创建回补计划，常规或临时调仓不能误入回补流程；
- 每个计划固定创建三批，各占减仓额 `1/3`，不改变原有 WeightTier；
- 第一批在 σₚ 回到 45% 以下后可执行；
- 第二批要求卡口连续通过 5 个交易日且原始风险信号消退；
- 第三批在连续通过 10 个交易日、无因子证伪时进入强制回补；
- 每批均须引用当前确认目标权重和新的 CalculationRun；若回补会越过 Policy Gate 则必须阻断；
- 因子证伪、目标权重未确认或前序批次未执行时均显式阻断；
- 状态变化使用追加式 `refill_batch_transition` 留存证据，不覆盖历史；
- 选择 `not_executed` 时必须书面记录理由，供季度复盘；
- 新增 `GET/POST /api/v1/refills`，支持创建、评估、执行留痕与读取三批状态。

真实 PostgreSQL 集成测试覆盖“只有风控减仓可创建计划”、第一批执行、第二批五日触发和完整三批状态读取。

## 第七切片：Catalyst、InvalidationCondition 与 ExitRestriction

- 新增追加式候选催化剂，保存预期日期、有效期、状态和可观察兑现结果；
- 催化剂有效期不得早于预期日期，避免不可解释的时间窗口；
- 新增结构化证伪条件，强制记录命题、可观察指标和明确触发条件；
- 新增主动清仓后的 `exit_restriction`，限制期精确为退出日起 90 天；
- 风控减仓明确不创建退出限制，保持策略规定的豁免；
- 限制可以引用外部执行记录，但 Epoch 不据此创建订单；
- 新增 `GET/POST /api/v1/governance`，支持催化剂、证伪条件、退出事件和当前限制查询。

真实 PostgreSQL 集成测试覆盖催化剂与证伪条件持久化、主动清仓限制，以及风控减仓不触发限制的关键边界。

## 第八切片：PlaybookBranch 与 ExceptionRecord

- 事件预案升级为追加式 `playbook_revision`，每次更新保留当时版本；
- 每个分支强制记录作用范围、场景、可观察触发条件、对应动作及对 σₚ 的方向影响；
- `ready` 预案至少包含一个分支；关键财报预案必须同时包含单标的分支和主线分支；
- 已有 `event_playbook` 继续保存当前摘要，历史修订与分支不被覆盖；
- 新增 `exception_record` 作为预案外“特事特看”补丁申请，强制记录未覆盖原因、不可逆逻辑变化和采取动作；
- 非紧急执行必须至少隔夜；同日执行必须写明冷静延迟豁免理由；
- 每条例外进入季度复盘，可标记为应吸收进预案或真实不可重复例外；
- 新增 `/api/v1/exceptions`，事件预案 API 同时返回新 revision ID。

真实 PostgreSQL 集成测试覆盖预案版本、单标的/主线分支、特事特看记录和季度吸收状态。

## 第九切片：Theme / ThemeVersion 主线版本

- 新增主题主对象、追加式主题版本、主题—候选关系与主题版本—证据关系；
- 主题版本区分安装期与部署期，并强制记录主线、盈利路径和证伪条件；
- 支持/反证证据角色不会因重复关联丢失；
- `GET/POST /api/v1/themes` 支持创建主题、保存版本、关联候选与证据；
- 真实 PostgreSQL 集成测试覆盖完整落库和回读。

## 第十切片：多周期 Review 与季度吸收

- 新增日常、周度、月度、季度和平仓后五种复盘；
- 复盘区分组合与单标的范围，单标的复盘必须绑定候选；
- 每次复盘绑定当时的策略版本、参数集和可选 CalculationRun；
- 结构化保存结论、有效部分、失效部分和后续动作；
- 只有已确认的季度复盘可以吸收特事特看或未执行回补；
- 特事特看必须明确标记为已固化或真实例外，不能用无结构文本静默关闭；
- `GET/POST /api/v1/reviews` 支持复盘写入、读取与季度吸收。

## 第十一切片：Operations 工作流聚合与页面闭环

- Operations 在原有风险、行情、覆盖和事件信号上，统一聚合回补状态、过期催化剂、待季度复盘例外、到期复盘和待确认主题版本；
- 派生事项继续使用稳定 ID 并确定性重建，不另建可漂移的待办数据库；
- 页面新增事件、主题和结构化复盘录入，保存后刷新即可看到新的事件视界与 Operations 状态；
- 调仓记录快照按《投资策略》5.1 归档触发类型、σᵢ/估计器/锚点、σₚ/Stress/卡口、权重档位三行理由、目标权重、异常项、动作和观察清单；
- 快照绑定 CalculationRun、策略版本与参数集，后续最新判断不会改写当时记录。
